# Поиск проблем

## `устройство не найдено`

Проверьте путь:

```bash
ls -l /dev/disk/by-id/
```

Лучше использовать стабильный путь `/dev/disk/by-id/...`, а не `/dev/sdX`.

## `smartctl` не видит диск через USB

Сначала:

```bash
smartctl --scan-open
```

Затем проверьте устройство вручную. Для некоторых USB/SATA-мостов нужен параметр `-d sat`:

```bash
smartctl -a -d sat /dev/...
```

Если это работает, добавьте в `[[disks]]`:

```toml
device_type = "sat"
```

## Тест идёт дольше расчётного времени

Это само по себе не означает отказ диска. Фоновый ввод-вывод способен увеличить продолжительность SMART-самотеста.

SMART Monitor добавляет запас к расчётному времени ATA-теста. Если и этот срок превышен, программа пытается остановить только тот тест, который запустила сама.

Проверить состояние вручную:

```bash
smartctl -a /dev/УСТРОЙСТВО
smartctl -l selftest /dev/УСТРОЙСТВО
```

## В журнале `Aborted by host`

Если перед этим SMART Monitor сообщил о превышении времени и успешной остановке, такая запись ожидаема: это результат `smartctl -X`.

Она не означает автоматически физическую неисправность накопителя.

## Уже выполняется другой самотест

Программа не запускает новый тест поверх существующего и не останавливает чужой тест.

Проверьте:

```bash
smartctl -a /dev/УСТРОЙСТВО
```

Также убедитесь, что другой cron, `smartd`, панель NAS или ручной скрипт не запускает тесты по своему расписанию.

## systemd показывает `degraded`

```bash
systemctl --failed --no-pager --full
```

Если причиной является SMART Monitor, смотрите журнал конкретного режима:

```bash
journalctl -u smart-monitor@long.service -n 300 --no-pager
```

Код `1` не должен переводить службу в `failed`, если установлен пример службы с `SuccessExitStatus=1 4`.

## Matrix: `Connection refused`

Проверьте адрес из конфигурации и реальный адрес, на котором слушает Synapse:

```bash
ss -lntp | grep -E ':8008|:8448'
```

Если Synapse опубликован только на конкретном адресе Docker-сети, `127.0.0.1:8008` работать не будет.

Проверка API:

```bash
curl -fsS http://АДРЕС:8008/_matrix/client/versions
```

## Не приходит резервное SMS

Проверьте:

- `sms_fallback.enabled = true`;
- выбран Telegram и/или MAX;
- `modem_url` и `phone`;
- общая блокировка модема;
- доступность Huawei API.

Если блокировка занята другой программой дольше `lock_wait_seconds`, SMART Monitor не полезет в модем параллельно и зафиксирует ошибку доставки.

## Предупреждение остаётся после устранения причины

Часть SMART-счётчиков и журналов накопительная. Например, `UDMA_CRC_Error_Count` и журнал ошибок не обязаны обнуляться после замены кабеля. Журнал самотестов также хранит историю, но SMART Monitor оценивает текущий результат по его последней записи.

Проверьте исходные данные:

```bash
smartctl -a /dev/УСТРОЙСТВО
smartctl -l selftest /dev/УСТРОЙСТВО
```

SMART Monitor 1.0.0 не хранит базовую линию предыдущих значений, поэтому намеренно показывает то, что находится в SMART сейчас.
