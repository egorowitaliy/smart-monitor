# Безопасность

## Права процесса

На большинстве Linux-систем для чтения полного SMART и запуска самотеста нужны права root. Поэтому пример systemd запускает SMART Monitor от root.

Это делает особенно важными права на конфигурацию и предсказуемое поведение программы.

## Выполнение внешних команд

`smartctl` запускается напрямую через `subprocess` без shell. Значения из конфигурации не вставляются в командную строку оболочки.

Для USB-мостов поддерживается только отдельный параметр `device_type`, который передаётся как значение `smartctl -d`. Произвольные дополнительные аргументы `smartctl` из конфигурации не принимаются.

## Токены уведомлений

Токены можно хранить:

1. непосредственно в `/etc/smart-monitor/config.toml`;
2. в `/etc/smart-monitor/secrets.env` и ссылаться на имя переменной через `*_env`.

Оба файла должны быть доступны только root:

```bash
chmod 600 /etc/smart-monitor/config.toml /etc/smart-monitor/secrets.env
```

В репозиторий реальные токены, номера телефонов и внутренние адреса добавлять не нужно.

## Сетевые запросы

Telegram и MAX используют HTTPS.

Matrix также рекомендуется использовать через HTTPS. Обычный HTTP допустим только в доверенной локальной сети, например между хостом и локальным Synapse.

Huawei HiLink обычно работает по HTTP внутри локальной сети. Поэтому доступ к сети модема следует ограничивать на уровне маршрутизации и firewall.

## Общая блокировка Huawei

Если к одному модему обращаются несколько программ или контейнеров, они должны использовать один физический файл блокировки.

SMART Monitor держит блокировку на протяжении всей операции резервного SMS, включая получение токена, отправку и необязательную точечную очистку сообщения.

## Очистка отправленных SMS

Программа не удаляет всю папку отправленных сообщений.

До отправки снимается список существующих сообщений. После отправки удаляется только один новый `Index`, если он однозначно совпадает с номером и текстом сообщения SMART Monitor. При неоднозначности удаление не выполняется.

## Ограничения SMART

Хорошие показатели SMART не гарантируют, что накопитель не откажет внезапно. SMART Monitor не является заменой резервного копирования, RAID и проверки восстановимости резервных копий.

Некоторые показатели SMART и биты результата `smartctl` являются накопительными. Например, старые записи журнала ошибок и CRC-ошибки могут сохраняться после устранения причины. Версия 1.0.0 не ведёт собственную базу предыдущих значений и поэтому оценивает текущее содержимое SMART, а не только прирост счётчиков. Для журнала самотестов текущая оценка строится по последней записи, чтобы старый неуспешный тест не создавал постоянное предупреждение после нового успешного теста.

## Сообщение об уязвимости

Если обнаружена проблема безопасности, не публикуйте рабочие токены, внутренние адреса или другие секреты вместе с отчётом. Для воспроизведения достаточно обезличенного примера.
